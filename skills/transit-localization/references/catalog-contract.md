# カタログの形式と文脈

## 記録する場所

`.xcstrings` はJSON。ルートの `sourceLanguage` / `strings` / `version`、既存の抽出メタデータを維持する。ユーザーが入力した1言語は該当localeの `stringUnit.value` に正確に記録する。カタログ全体の基準言語を入力言語へ変更する必要はない。

各キーに必要な文脈はキー直下の `comment` に1つの文字列として記録する。行を分ける場合はJSON文字列の `\n` を使う。書く内容の例：

- 使用画面と役割：履歴の取引種別、設定ボタン、権限説明。
- 誤訳しやすい意味：「カード残高」「チャージ金額」「運賃支払い」の区別。
- 引数の意味と順序：第1引数=地域、第2引数=都市、金額引数に通貨単位を含むか。
- 固有名詞・略称：正式なカード名、表示用短縮名、翻訳せず維持する名前。

Issue番号、実装者、作業ログだけのコメントは翻訳文脈にならない。確認できない仕様値・取引分類・地域を付け足さない。

## 現行のキー規約

リポジトリの現行規定と使用箇所を正とする。代表例は `cardList.<id>` / `.description` / `.sortName`、`<id>.short` / `.scand.description`、`card.*`、`result.history.*`、`scanner.*`。`.scand.description` 等の既存綴りを翻訳補完と同時に改名しない。

KAIの現行IDは `idKAI`。旧 `idKMT` の名前を新しい翻訳キーとして再追加せず、保存互換性は `Utility/CardIdentity.swift` で扱う。

## 形式と引数の実例

- `currency.jpy.%@` は金額引数と通貨表示。単位を二重に付けない。
- `issue.cityNameLocalize:%@,%@` は言語で順序が違う。英語の `%2$@, %1$@` と日本語の `%1$@ %2$@` は同じ引数を参照する。単純な文字列順の一致検査では判断しない。
- `result.history.fare` は現行表示がFare／運賃支払い。過去の `Used Location / 利用場所` というcommentは用途と一致しないため、既存commentを無条件に正解として流用しない。

既存コードやカタログは表現形式の参考であり、訳語・文脈の意味が常に正しい証拠ではない。

## 対応しない変換

JSONC化、独自コメント属性の追加、他言語の一括削除、すべての文字列への同じcommentの付与、中文の字形変換だけでの完了扱いはしない。複数形の `variations` や `substitutions` を通常のstringUnitに潰してはいけない。
